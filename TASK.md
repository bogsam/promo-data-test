# Тестовое задание на вакансию PHP-разработчик

## Технологии:
- PHP 8.x
- Laravel
- PostgreSQL
- CSV-файл для отчёта (без генерации XLSX)
- Laravel Migrations для создания структуры базы данных

## Пользовательская постановка

Необходимо реализовать механизм формирования отчёта по товарам выбранной категории с минимальной и максимальной ценой за последние 7 дней,
с сохранением CSV-файла и ведением журнала выполнения процесса с возможностью последующего контроля и скачивания отчётов.

## Задача
Реализовать задачу с использованием фреймворка Laravel.
Структура базы данных должна быть создана с использованием миграций.
Проект должен быть выложен на GitHub или Bitbucket.

## Пункт 1 — Создание таблиц и генерация отчета
1. Таблицы:
    - manufacturer: Хранит информацию о производителях.
        - manufacturer_id — автоинкрементный первичный ключ.
        - manufacturer_name — наименование производителя.
    - product: Хранит информацию о товарах.
        - product_id — автоинкрементный первичный ключ.
        - product_name — наименование товара.
        - category_id — идентификатор категории товара.
        - manufacturer_id — внешний ключ на производителя.
    - price: Хранит информацию о ценах на товары.
        - price_id — автоинкрементный первичный ключ.
        - product_id — идентификатор товара.
        - price — цена товара.
        - price_date — дата цены.
2.  Команда для формирования отчета:
    - Принимает параметр — идентификатор категории товара (category_id).
    - Генерирует CSV-файл, где дата/время в имени — это дата/время запуска команды:
      report_{manufacturer_id}_{category_id}_{ГГГГ-ММ-ДД_ЧЧ-ММ-СС}.csv.
    - В отчете должны быть следующие столбцы: manufacturer_name, product_name, price, price_date.
3.  Требования:
    - По каждому товару выводить две строки, с минимальной и максимальной ценой за последние 7 дней от текущей даты.
    - Если для указанной категории нет товаров — вывести сообщение об ошибке.
    - Цена товара должна быть округлена до двух знаков после запятой.

## Пункт 2 — Логирование процесса
1.  Таблица  report_process  :
    - Хранит информацию о ходе выполнения отчета.
    - Поля:
        - rp_id — автоинкрементный первичный ключ.
        - rp_pid — идентификатор процесса.
        - rp_start_datetime — дата/время начала процесса.
        - rp_exec_time — время выполнения.
        - ps_id — статус процесса.
        - rp_file_save_path — путь к сохраненному файлу.
2.  Таблица process_status:
    - Содержит статусы процессов.
        - ps_id — первичный ключ.
        - ps_name — наименование статуса (например, "Запуск", "Завершен", "Ошибка").
3.  Логика:
    - При запуске процесса добавить запись в таблицу report_procсes со статусом "Запуск".
    - После завершения отчета обновить статус на "Завершен" или "Ошибка" в случае сбоя.
    - Логирование ошибок должно происходить только в случае фатальных ошибок (например, невозможности записи файла или сбоя при запросе данных).

## Пункт 3 — Страница контроля выполнения процессов
1.  Страница:
    - Заголовок страницы — "Контроль выполнения процессов".
    - Табличное представление:
        - Дата процесса (rp_start_datetime).
        - Время запуска и время выполнения (rp_exec_time).
        - Идентификатор процесса (rp_pid).
        - Статус процесса (ps_name).
        - Имя файла (rp_file_save_path).
2.  Функционал:
    - Статическая таблица с информацией из таблицы report_process.
    - Строки с процессами в статусе "Ошибка" должны подсвечиваться красным.
    - Для строк с успешными процессами поле "Файл" должно быть гиперссылкой, по которой можно будет скачать файл (по пути,
      указанному в rp_file_save_path).

    ## Технические требования:
    1. Используйте Laravel Migrations для создания структуры базы данных.
    2. Логируйте ошибки с помощью встроенного логгера Laravel.
    3. Для страницы контроля можно использовать Blade (шаблонизатор Laravel) без динамического обновления с использованием JavaScript.
